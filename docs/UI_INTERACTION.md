# 页面结构与交互

## 单页布局（桌面优先，1440px）

```text
┌ Top bar: Organization Capability Radar | Reset demo | Play/Pause | Step ┐
├─────────────┬───────────────────────────────┬──────────────────────────┤
│ 项目/群聊列表 │ 模拟飞书群聊（业务现场）       │ Capability Radar          │
│ US Launch   │ 消息流 + 播放进度               │ 1. Signals timeline        │
│             │                               │ 2. Capability gaps cards   │
│             │                               │ 3. Recommended actions     │
└─────────────┴───────────────────────────────┴──────────────────────────┘
                                                  ↓ 点击卡片
                                      右侧抽屉：证据、推理、行动、Brief
```

## 状态与交互

1. 初始：群聊显示全部消息但未播放的内容半透明；雷达为空，显示“等待业务信号”。
2. Play：每 5 秒激活一条消息，带小动画；其对应的信号同时进入 Signals timeline。
3. 聚合阈值满足时：缺口卡片出现，标注 New；高优先级卡片置顶。
4. 点击缺口：打开抽屉，依次显示 Summary、Evidence、Action options、组织设计建议；仅在 Recruit 达到阈值时显示“招聘能力画像草案”。
5. Step：只推进一条，方便讲解；Reset 恢复初始状态。
6. “Create Hiring Request”：P0 中为非写入式预览按钮，弹出“Demo：实际集成将通过 ATS Adapter 创建草稿”。

## 视觉原则

- 让群聊像飞书但不使用其商标/精确 UI；称为“团队协作消息”。
- 重点色仅表达优先级：低灰、Medium 琥珀、High 珊瑚红；不要把置信度和风险混为一色。
- 每一个判断旁均可点击到“为什么”；避免黑箱仪表盘。招聘能力画像必须标注“Agent 草案，需 HRBP 与技术负责人确认”，且展示它引用的证据。
- 首屏不要出现复杂图表。使用卡片、短标签与时间线即可。

## 空/错误状态

- 无信号：说明“播放对话以开始感知”。
- 低置信度：展示“继续观察”，不给强行动。
- 规则数据异常：在开发模式显示可复制的错误，不影响重播。
