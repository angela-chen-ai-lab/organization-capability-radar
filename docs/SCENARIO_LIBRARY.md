# 案例库｜从局部硬伤到系统性组织能力诊断

## 使用原则

案例不是为了让系统“猜出该招什么人”，而是用于检验它能否避免错误归因。每个场景都要先明确：这是局部硬伤，还是需要改变组织能力系统的问题？所有公司、人名、数字均为虚构，可公开演示。

## 场景 A｜美国版支付故障：局部硬伤对照组

**表层症状**：Stripe webhook、退款同步异常，影响美国版上线。

**正确诊断**：这是高紧急度的项目交付风险，却只有一个窄技能点和一个具体项目。即便团队暂缺此经验，也不能仅凭当前证据推出“招聘支付工程师”：工作量不连续，单一技能很难饱和。

**应显示的建议**：

- Now：采购 Stripe 实施/排障服务或临时专家（Outsource）。
- Next：对现有后端做短训与知识沉淀（Train）。
- Not recommended now：新增全职岗位（Recruit），除非同类信号跨多个市场/产品持续出现，且支付被确认为长期核心能力。

**Demo 价值**：它让观众看到系统不会把每一个紧急痛点都“医疗过度”成招聘。

## 场景 B｜IP 跨品类开发：系统性组织能力缺口（主场景）

### 业务背景

一家以 IP 为核心经营潮玩、游戏机/电动玩具、毛绒公仔、卡牌等衍生品的公司，仍按产品品类建立独立部门。一个爆款 IP 可同时跨多个品类开发，但 IP 的商业价值、节奏与用户洞察被分散在不同部门。技术研发人员既要懂软硬件，又要在非标准产品之间快速迁移；市场上同时满足这一组合的人很少，而在单个品类团队中又常常工作量不饱和。

### 系统症状（既不是单个人的问题，也不能只靠改组织解决）

| 来自哪里 | 可观察信号 | 隐含问题 |
|---|---|---|
| 电动玩具项目组 | 等待 IP 设定与公仔团队确认，错过原定打样窗口 | 同 IP 没有共同节奏与决策接口 |
| 毛绒公仔项目组 | IP 上线后才得知电动玩具已有互动玩法，无法共同包装 | 信息与创意被产品部门边界截断 |
| 卡牌项目组 | 同一 IP 的世界观/角色设定版本不一致，反复返工 | 缺乏 IP 级资产管理/治理 |
| 技术负责人 | 每个产品都要完整软硬一体研发；招全能人才极难，招到又不饱和 | 能力组合与组织配置方式错配 |
| HRBP | 不同部门分别要“全能研发”，画像重叠又互相抢人 | 招聘困境是下游症状，不是根因 |

### 系统诊断假设

**能力缺口**：`ip_lifecycle_orchestration`（IP 生命周期经营与跨品类协同）与 `cross_domain_product_engineering`（跨软硬件、跨品类的产品工程能力）。前者是组织机制缺口，后者是研发人才供给缺口；两者相互放大。

**系统性驱动因素**：

1. `structure`：组织仍以品类部门为唯一权责中心，未设 IP 级 Owner/协同单元。
2. `operating_model`：同 IP 的立项、创意、设计、打样、上市没有共同节奏、里程碑与决策机制。
3. `capability_portfolio`：将稀缺的跨域技术迁移能力重复嵌入各品类，而非作为共享能力建设。
4. `resource_allocation`：人才按部门固定占有，峰谷无法跨 IP/品类流动。

这是待管理层验证的诊断假设，不是系统对组织架构的自动裁决。

### 推荐的行动组合

| 时间 | 建议 | 对应 Action | 为什么 |
|---|---|---|---|
| 现在 | 为重点 IP 建立 IP Owner、跨品类例会、统一角色/世界观资产与共同里程碑 | 组织设计建议（扩展 Action） | 先打通协同与决策界面 |
| 30–90 天 | 建立共享的跨域产品工程能力池；从各品类临时抽调人员组成 IP 虚拟团队 | Internal Mobility | 让现有能力围绕 IP 流动，而不是被部门锁定 |
| 30–180 天 | 训练“软硬一体 + 技术迁移 + IP 产品化”能力，建立轮岗/复盘机制 | Train | 扩大复合能力供给 |
| 现在起持续进行 | 招聘跨域研发核心人才：拥有软硬一体基础、对非标准产品有技术迁移能力，并愿意在团队组合中补齐深度 | Recruit | 这是刚性研发供给，不是可被组织调整替代的“可选项”；难点在于市场上不存在大量即插即用人选，必须重写画像、优化评估，并预留培养/组合空间 |
| 峰值 | 对标准化模块/产能高峰使用外部合作团队 | Outsource | 保持弹性，避免为波峰永久扩编 |

这不是“先改组织、再考虑要不要招人”的串行关系，而是并行关系：没有 IP 级机制，新招研发仍会被锁在品类孤岛；没有足够研发供给，新机制也没有可跨品类调度的基础能力。

`AI Enablement` 在本案例可辅助进行 IP 资产检索、版本一致性校验、跨群纪要与依赖提醒，但不能替代 IP Owner、跨品类决策或技术架构责任。

### Agent 在两周对话后的期望输出（而非素材中的结论）

系统应在 D5 后形成“跨域产品工程人才供给”缺口，在 D6–D7 后将其与“IP 生命周期经营与跨品类协同”缺口关联为一个系统诊断。D7 中的管理层只提出未解问题；以下结论、优先级与行动组合必须由 Agent 的证据聚合界面呈现。

**轨道一：研发能力供给（Recruit + Train）**。持续招聘核心跨域研发人才；岗位画像强调系统思维、一个或两个扎实专业锚点、跨产品迁移能力与学习速度。用成对/小队式搭配和明确成长路径弥补市场上难以找到的“全能即插即用”人选。

**轨道二：能力的组织化（Internal Mobility + 组织设计建议）**。建立 IP Owner、共同资产版本 Owner、跨品类里程碑和共享研发能力池；让研发人才在重点 IP 阶段进入虚拟团队，以统一优先级调度，而不是被永久锁定在某一品类部门。

Outsource 只应用于标准化模块、样机高峰或临时产能；AI Enablement 用于版本检索、依赖提醒、纪要和知识沉淀。它们都不替代上述两条主轨。

此处不是一张普通 JD，而是 Agent 基于证据生成、供技术负责人和 HRBP 共同校准的 **招聘能力画像草案**。它应清晰说明“为什么招聘”“招聘怎样的能力组合”“哪些不要苛求于同一个人”，并保留人工确认入口。

| 优先能力（Strong preference） | 消费电子、智能硬件、机器人、互动玩具等非标准实物产品经历；小批量试制、供应商协同或整机调试经验 | D1-04、D3-02、D5-01 |
| 不应写成硬门槛 | 同时精通结构、电子、嵌入式、App、项目管理；已经做过完全相同品类；“来了就能独立覆盖所有环节” | D5-02–D5-04 |
| 可通过培养补足 | IP/内容语境、特定品类工艺、内部资产体系、某一弱专业的基础知识；由配对机制和轮岗支持 | D5-04、D6-03–D6-04 |
| 作品证据（优先于简历罗列） | 提交 1–2 个可脱敏的实物产品作品档案：问题背景、本人职责、关键约束、至少一次失败/变更、最终取舍与结果。可为照片、原型视频、设计文档片段、测试记录、代码/电路/结构变更说明；不要求泄露前雇主机密 | D1-03–D1-06、D3-02–D3-04 说明关键价值在真实工程闭环 |
| AI 使用说明 | 每个作品档案附一页“AI 协作说明”：AI 用在何处（资料检索、方案发散、代码/文档初稿、调试辅助等）、哪些结论由本人验证、AI 建议何时被否决及为什么。使用 AI 不是扣分项；无法说明验证与责任边界才是风险信号 | AI 时代应验证判断、验证与责任，而非假设候选人完全不用 AI |
| 工作样本验证 | 给出“角色设定变更导致互动玩法变化”的短案例，允许候选人使用公开资料和 AI 工具。在 45–60 分钟内产出：需澄清的问题、结构/电子/软件受影响接口、最小验证方案、风险排序和与产品/供应商的沟通清单；重点观察问题定义、取舍与可验证性，而非文档文采 | 来自 D1-03–D1-06、D3-02–D3-04 的实际摩擦 |
| 复盘访谈 | 以作品和工作样本为材料追问：哪里是候选人亲自决策？AI/他人建议改变过什么？一个样机失败后如何缩小排查范围？如何让不同专业对同一接口达成一致？ | 验证作品真实性、工程判断与协作能力 |
| 入职后配置 | 不固定归属单一品类；先进入共享能力池，在一个重点 IP 中承担明确整机集成模块，并由另一专业伙伴互补 | D2-04、D5-05、D6-01–D6-04 |

**Agent 的解释文案示例：**“当前不是缺一位覆盖所有专业的‘全能研发’，而是缺少能在非标准产品间迁移、把多专业接口串成整机闭环的核心研发能力。建议采用两人互补招聘 + 共享能力池 + 项目轮转。评估应以脱敏作品档案、允许使用 AI 的工作样本和复盘访谈为主，验证候选人的工程判断与责任边界，而不只看简历关键词。请 HRBP 与技术负责人确认人数、专业锚点比例和薪酬带宽后，再生成正式 JD。”

### 公开资料校准说明

本案例的对话为原创虚构内容，未摘录真实聊天记录。行业背景参考了公开资料所述的 IP 驱动、多品类/供应链协同、长开发链条与复杂工序：例如 [36Kr 关于 IP 潮玩产业链的梳理](https://www.36kr.com/p/3488464720059525)、[36Kr 对潮玩生产工序与供应链协同的报道](https://www.36kr.com/p/3508669156726915)，以及关于复杂产品软硬件协同设计的[技术概述](https://www.zhihu.com/market/pub/120032914/manuscript/1289571849828470784)。这些资料仅用于校准场景真实感，不构成对任何企业的事实描述。

### 期望的系统输出

高优先级缺口卡应包含两张相互关联的卡：**IP 生命周期经营与跨品类协同能力**（`problemNature=systemic`）与 **跨域产品工程人才供给**（`problemNature=systemic`）。前者影响“爆款 IP 的跨品类变现速度与体验一致性”；后者影响“研发交付能力与可持续供给”。

证据抽屉需同时展示至少三个群组的消息，并显示推理：跨边界重复 + IP 商业目标与品类制组织边界冲突 + 跨域能力需求无法被单部门稳定承载。输出必须是双轨行动：组织机制与共享能力池 + 有针对性的研发招聘与培养，而非把其中任何一项降格为另一项的附属。
