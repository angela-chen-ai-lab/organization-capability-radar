# 3 分钟 Demo 演示脚本

## 演示前

选择「IP 跨品类开发」场景并点击 Reset，确保右侧为“等待业务信号”。浏览器缩放 100%，窗口宽度至少 1280px。

## 讲述与操作

| 时间 | 操作 | 讲述 |
|---:|---|---|
| 0:00 | 指向群聊 | “这不是一张招聘申请表，而是围绕同一个 IP 的跨品类业务现场。” |
| 0:15 | 点击 Play，播放 1–3 条 | “目标是把同一 IP 做成完整体验，但产品品类之间已经在等彼此的信息和决策。” |
| 0:45 | 播放 4–6 条 | “返工、版本不一致和招聘难同时出现。它们看起来不同，其实可能是一个系统性问题的不同症状。” |
| 1:15 | 播放 7–8 条 | “现在雷达不会显示‘缺一名工程师’，而是形成跨品类协同与 IP 生命周期经营的能力缺口。” |
| 1:35 | 点击缺口卡片，打开 Evidence | “这里的证据来自多个部门：跨边界重复，是诊断系统性问题的前提。” |
| 1:55 | 展开 Action options | “这是双轨方案：IP 级协同机制和共享能力池，同时必须补足跨域研发人才；内部流动、培养与弹性外包共同配合。” |
| 2:25 | 打开组织设计建议，再打开“招聘能力画像草案” | “注意：两周的原始对话里没有人给出这个结论。这是 Agent 汇总多群证据后的建议。它既不把结构问题交给新员工，也不假装研发能力可以凭空出现。” |
| 2:45 | 指向结论 | “Nobody submitted a hiring request. The organization discovered a systemic capability gap.” |

## 常见问题回答

- “这是在监控员工吗？”——P0 只用公开模拟数据。生产版本必须按场景授权、最小化采集，并聚焦团队能力而非个人绩效。
- “AI 会自动招人吗？”——不会。它提供可解释建议，最终决策和外部写入由人完成。
- “为什么不用 LLM？”——先用可复现规则证明产品机制；LLM 是未来增强而非 Demo 成败前提。
