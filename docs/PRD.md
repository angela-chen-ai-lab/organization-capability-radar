# PRD｜组织能力感知系统 Demo v0.1

## 1. 产品定位

Organization Capability Radar（暂定名）从业务协作信号中发现组织当前及将来的能力缺口，汇总可核验的证据，帮助管理者在五类补足方式中作出建议，而非默认“外部招聘”。它尤其要识别无法被“补一个人”解决的系统性问题：组织边界、协同机制、能力组合与资源配置之间的错配。

核心链路：**业务活动 → 信号 → 能力缺口 → 证据聚合 → Action 决策 → 可执行 Brief**。

## 2. 用户、问题与成功标准

主要用户：业务负责人、HRBP、人才/组织发展负责人。演示观众：潜在共创者、产品/HR 从业者。

要解决的问题：招聘需求通常依赖业务部门人工提出，信息滞后且只表达“职位”。更深层的问题是，反复出现的招聘难、协作失灵和项目返工，可能是组织系统的症状，却被拆成一张张孤立的岗位申请。Demo 证明系统可以先识别“能力”和“系统原因”，再决定 Recruit、Internal Mobility、Train、Outsource 或 AI Enablement；必要时还应建议组织设计调整。系统不把招聘当作万能药，也不因组织问题存在就取消招聘这一基础能力建设。

成功标准（现场 3 分钟内）：

1. 观众看懂左侧群聊是业务现场，右侧是实时组织能力雷达。
2. 观众可追溯每个高优先级判断到具体消息证据。
3. 观众看到系统不会因单点故障直接招人，并能区分局部修复与系统性能力缺口。
4. 观众看到跨产品、跨项目的证据如何导向“组织设计/协同机制”建议。
5. 点击后能查看可交给 HR 的 Hiring Brief（仅当 Recruit 为推荐项）。

## 3. P0 功能与验收

| 功能 | 说明 | 验收 |
|---|---|---|
| 模拟飞书群聊 | 播放、暂停、重播预置消息；支持逐条推进 | 60–90 秒内可完成一轮播放 |
| 信号提取 | 每条已播放消息生成 0–n 个结构化信号 | 信号可在右侧按时间出现 |
| 缺口雷达 | 展示能力名称、优先级、置信度、影响和状态 | “国际支付集成”最终为 High/High |
| 证据抽屉 | 点击缺口查看引用消息及其推理链 | 每条结论至少有两条可见证据 |
| 行动建议 | 五类人才/能力行动按推荐度排序，并给出理由 | 不把建议硬编码为“招聘”；系统性场景可另给出组织设计建议 |
| Hiring Brief | Recruit 是推荐项时生成结构化摘要 | 包含 Why now、能力、证据、must-have |

## 4. 明确边界

- 所有名称、对话、员工档案均为虚构；不得上传真实聊天记录。
- 系统提供建议，不自动创建岗位或做用工决策。
- 如生成招聘能力画像，候选人验证默认采用脱敏作品证据和允许使用 AI 的工作样本；不以“是否使用 AI”作为排除条件。
- 不推断个人绩效、性格、敏感身份或就业资格。
- P0 的规则是可读、可调、可复现的；后续模型输出必须标注为“AI 建议”。

## 5. 关键用户旅程

业务负责人进入页面，选择「IP 跨品类开发」场景。系统从电动玩具、毛绒公仔、卡牌等产品组的对话中，识别到同一 IP 被分割管理、跨品类开发反复错过窗口、技术人员被按单一产品占用，且岗位画像长期相互矛盾。跨项目证据聚合后，系统形成“IP 生命周期经营与跨品类协同能力”系统性缺口。诊断同时给出两条并行结论：产品制部门边界与 IP 驱动商业模式错配，必须建立 IP 级协同机制和共享能力池；同时，跨软硬件、跨非标准产品迁移的研发能力供给不足，必须招聘并培养关键研发人才。组织重塑让人才被有效配置，人才招聘让新机制有能力可调度，二者缺一不可。

## 6. 非目标（P0）

真实 IM 接入、自动发消息、真实内部人才匹配、自动 JD 发布、AI 简历筛选、多租户、权限管理、模型训练与生产级合规审计。
