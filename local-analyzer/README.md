# Local Analyzer｜本地能力洞察分析器

这是 Organization Capability Radar 的第二种产品形态：让拥有明确授权的人，在自己的浏览器中导入、脱敏并初步审阅协作记录。

它和互动 Demo 的关系是：

```text
互动 Demo：说明产品假设和 Core 的工作方式
本地分析器：用明确授权的真实记录，验证 Core 是否有价值
未来平台 Adapter：在飞书等平台中，以最小权限把消息送入同一 Core
```

## 开发状态

当前仍在本地开发，尚未作为完整产品形态发布到 GitHub。现有原型实现了：

- JSON、Markdown 和 TXT 本地导入；
- 浏览器内的发言人代号化、手机号、邮箱、长号码、链接和自定义词替换；
- 授权与人工脱敏复核闸门；
- 开放式协作摩擦候选发现、最小证据门槛和反证提示；
- 匿名化人工复核包导出。

当前版本的呈现形式是：**用户在本机浏览器中打开网页，并在网页内完成导入、脱敏、选择自己的模型 API 与查看结果。** 它不是 Windows 安装程序；现阶段这正是有意保持轻量的选择。

正在实现的正式用户工作流是：

```text
导入 JSON / Markdown
→ 统一为内部消息结构
→ 本地脱敏与人工预览
→ 选择模型、临时输入自己的 API Key
→ 明确确认仅发送脱敏副本
→ Capability Orchestration Core 约束模型分析
→ 能力缺口、证据、行动组合与人工追问
```

API Key 只保留在当前页面内存中；刷新、清除记录或关闭页面后即丢失。浏览器直连某些模型服务可能受到跨域限制，届时会提供本机桥接程序，但桥接程序同样不保存原始记录或 Key。

## 发布前必须完成

1. 将界面、逻辑、文档、虚构样例和测试统一放入此文件夹，不再散落在项目根目录。
2. 增加 JSON Adapter 的字段映射配置，不能靠猜测真实导出格式。
3. 增加数据质量页：时间窗、缺失字段、重复消息和解析失败原因。
4. 将规则型探索与未来的模型 Adapter 明确分层；默认不开启外部模型。
5. 使用完全虚构的样例进行端到端测试；任何真实试点记录始终留在本地私密目录。
6. 完成至少一轮人工复核，记录误判、遗漏和有价值的行动建议。

## 输入适配层：开放共创接口

当前版本可靠支持结构化 JSON、Markdown 与 TXT。它不会假装能从截图、PDF 或没有消息边界的自由文本中恢复完整聊天结构。

未来的 `Input Adapter` 负责把不同输入转为同一种 `CanonicalConversation`，再交给本地脱敏与 Core。它是一个适合共创的模块：

- 微信/飞书等导出的不同 JSON 字段映射；
- 多条转发聊天的拆分与顺序恢复；
- 截图 OCR、发言人/时间/消息边界识别，并明确标记不确定性；
- Word、PDF、表格等文件的提取；
- 用户手动确认“哪一列是时间、发言人、正文”的映射界面。

任何 Adapter 都必须遵守：不能编造缺失的时间、发言人或消息顺序；无法可靠恢复时，必须降级为“文本主题分析”，不能声称完成组织能力诊断。详细契约见 [INPUT_ADAPTER_CONTRACT.md](INPUT_ADAPTER_CONTRACT.md)。

## 不做什么

- 不上传聊天记录，不写入浏览器持久化存储；
- 不对个人评分、排序或预测；
- 不自动提交招聘、调动、培养、采购或组织调整；
- 不在没有明确批准的情况下调用任何外部模型 API。
